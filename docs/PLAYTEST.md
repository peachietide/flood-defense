# 试玩协议 · 第一轮

> 目的：拿到第一手行为数据，回答三个问题——**好不好懂、好不好玩、会不会再玩**。
> 时间：一人 15 分钟，3–5 人即可。
> 不需要技术背景，也不需要懂水文。

---

## 一、招募

**建议 3–5 人**，混合两类：

| 类型 | 人数 | 为什么 |
| --- | --- | --- |
| 完全不懂行的人（室友、朋友） | 2–3 | 测"简单易用"这条要求 |
| 懂一点工程/水文的同事 | 1–2 | 测"专业性"是否站得住 |

**不要招**：已经看你演示过的人（他已经知道怎么玩了，数据无效）。

## 二、准备

```
✔ 一台电脑，浏览器打开 dist/index.html
✔ 手机计时器（或用手机录像）
✔ 一张记录表（见第四节）
✔ 提前清空浏览器 localStorage（保证每人从零开始）
```

**关键规则：全程不要提示、不要解释、不要替他操作。**

他问"这个是什么意思"——你只回答：**"你觉得呢？"**

## 三、任务脚本（照着念）

### 开场（30 秒）

> "这是一个防洪的小演示，我想看看它好不好用。没有标准答案，你随便玩，我不会提示你。我会在旁边记点东西，不用管我。"

### 任务 1：第一印象（1 分钟）

> "打开这个页面，你先跟我说说，你觉得这个东西是干嘛的？"

**记录**：他第一眼看哪里？有没有说"看不懂"？

### 任务 2：第一次操作（3 分钟）

> "假设你是这个变电站的负责人，马上要下暴雨了，你要做点准备。你会怎么做？"

**记录**：
- 从打开到第一次点击，用了多少秒
- 他先点了哪个按钮（加高 / 水泵 / 场景）
- 有没有犹豫、鼠标来回移动
- 有没有问"这个按钮是干嘛的"

### 任务 3：完整一局（5 分钟）

> "好，那你开始下雨，看看会怎么样。"

**记录**：
- 他选了 5 次加高还是混着用泵
- 中途有没有说"啊""哦"（顿悟时刻）
- 输了之后的第一反应（重开？关掉？问为什么？）

### 任务 4：换一个场景（2 分钟）

> "换一个场景试试，这个和刚才有什么不一样？"

**记录**：他有没有发现场景描述里的"难点"那一行。

### 任务 5：收尾提问（3 分钟）

> 1. "如果要给同事用，你觉得他最多能忍多久不看说明？"
> 2. "哪个地方最让你困惑？"
> 3. "你还会再玩一次吗？为什么？"

**注意**：第 3 题的回答**不要信**——看他有没有真的点"重来"。**行为比回答可信。**

## 五、数据怎么用

每次试玩后，点页面左下角的 **"导出试玩记录"**，会下载一个 JSON。

里面每条会话长这样：

```json
{
  "id": "a1b2c3d4",
  "startedAt": "2026-10-23T02:11:00.000Z",
  "scenario": "canyon",
  "rainScale": 1,
  "events": [
    { "at": 1200, "type": "session_start" },
    { "at": 8400, "type": "first_action", "data": { "kind": "place" } },
    { "at": 9100, "type": "place", "data": { "tool": "levee", "x": 55, "z": 89, "ok": true } },
    { "at": 22000, "type": "start", "data": { "budgetLeft": 880, "pumps": 0 } },
    { "at": 61000, "type": "result", "data": { "won": true, "hp": 100, "budget": 880, "elapsed": 45 } }
  ]
}
```

### 三个最该看的数字

| 指标 | 怎么算 | 说明什么 |
| --- | --- | --- |
| **首次操作耗时** | `first_action.at` | > 15 秒 = 界面有理解成本 |
| **重开次数** | `restart` 事件数 | 0 次且失守 = 挫败感太强或不想玩 |
| **工具偏好** | `place` 里 tool 的分布 | 某工具从没被用过 → 它可能是鸡肋 |

### 判定标准（建议）

| 现象 | 判定 |
| --- | --- |
| 超过一半人首次操作 > 20 秒 | 界面需要简化 |
| 超过一半人第一局就放弃（没重开） | 难度或引导有问题 |
| 水泵使用率 < 10% | 水泵该改或该删 |
| 所有人都只选 50 年重现期 | 其他档位没有被发现，或没有意义 |

## 六、迭代

拿到 3–5 条记录后：

1. **列出所有"卡点"**，按出现频率排序
2. **只改前三名**，别一次改十处（否则不知道是哪个改动生效了）
3. 改完**再找人玩一轮**，对比同一个指标

**一轮只验证一个假设，是最快的做法。**
